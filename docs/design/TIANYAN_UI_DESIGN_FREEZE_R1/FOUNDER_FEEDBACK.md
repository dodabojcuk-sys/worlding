# 创始人反馈冻结 — R1

> R0 设计稿未通过创始人视觉与体验验收。本文作为 R1 的唯一输入约束，不允许改写为“基本通过”“只需微调”或“接近目标”。

## A. R0 明确结论：FOUNDER_VISUAL_REJECTED

- R0 女娲与世界观高保真原型在 2026-09-05 提交后，经创始人直接审阅，未获认可。
- 核心问题不是“细节没对齐”，而是信息层级、作者工作流主次与女娲辨识度均未达到产品目标。
- 本轮 R1 为独立重做，必须在隔离设计分支完成；创始人通过前禁止进入生产代码。
- PR #30 继续保留为历史记录与资产来源，但不作为已冻结目标。

## B. 女娲问题

1. **功能可见性不足**
   - R0 默认态过分强调“简洁”，把大量真实功能（范围设置、分支版本、授权状态、运行记录、手动采纳/创建节点）折叠到难以一眼找到的位置。
   - 部分功能仅出现在 `details` 或侧栏次级页签中，默认不可见。

2. **“接下来的走向”区域过大**
   - 默认态即显示三张等宽大卡，视觉重心压过正文舞台。
   - 方向卡与正式正文同权重，容易让作者误以为候选就是将要发生的正式情节。

3. **正文主位不足**
   - 1440 默认态中，正文舞台被场景头、Run 条、候选卡和 composer 挤压，稿纸感没有出来。
   - 场景头、运行状态和技术信息在视觉上与正文平级甚至更强。

4. **功能矩阵登记不等于可用**
   - R0 矩阵把 17 项功能全部“登记”了位置，但若干位置是在展开区、次级按钮或预留态，可发现性差。
   - 不能再用“映射率 100%”掩盖可发现性问题。

5. **预留功能占据真实界面**
   - “角色访谈 / 角色接管 / 作者干预”等尚未实现的模式以 chip 形式平铺在 composer 首行，视觉上与“与女娲共创”并列。
   - 预留功能必须明确标识且不可点击，不能占据默认主工作面。

6. **整体过于文档化，缺少女娲身份**
   - R0 女娲看起来更像一个后台控制台或文档管理页，而不是“作者与 AI 共演故事的舞台”。
   - 缺少命运织线、轨迹、墨线稿纸等女娲应有的视觉符号；白卡堆叠感强。

## C. 世界观问题

1. **展示看板大于作者工作流**
   - 默认首屏同时铺开世界脉搏四块、因果网络 SVG、历史与演化时间线、类型化对象卡片全集，像一个“世界设定报告”。
   - 作者进入后不知道该先做什么，缺少明确的“下一步动作”。

2. **默认因果网络过重**
   - 大型 SVG 网络在首屏占据核心位置，但多数节点尚未有正式证据，容易把示意当成事实。
   - 因果网络不应作为默认首屏内容。

3. **世界脉搏、时间线、对象浏览互相抢层级**
   - 四块脉搏横带、纵向演化轨、卡片网格在同一屏竞争注意力。
   - 缺少主次分区，阅读动线被切割成多块信息展板。

4. **缺少明确的编辑 / 新建 / 关联 / 冲突处理 / 补全入口**
   - R0 有“资料编辑 / 地图 / 关系”按钮，但新建资料、编辑当前对象、关联当前场景、查看冲突、标记待确认等真实动作没有在工作面中形成稳定入口。
   - 搜索第二状态只展示结果，没有与“任务完成”形成闭环。
