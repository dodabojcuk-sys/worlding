## 本轮 OBS-0 范围

1. **目录恢复：**隔离夹具创建并确认“雾港”单元，冷启动和已持久化目录状态各走一次；失败区分初始化、读取、分类投影和点击阶段。2026-09-06 的远端 trace 证明同页消费者重复发出 6 次 World Library 与 4 次 Story Unit 读取，目录自己的结果到 47.6 秒才提交，晚于原 30 秒操作断言；服务端并非空数据，React 也没有在完成后丢状态。修复后目录断言通过；完整 E2E 随后暴露的假流超时属于长场景末尾负载污染，因此保留全部断言，但改为同一 `npm run test:e2e` 总 gate 中使用独立 fixture/API/浏览器子场景执行。
2. **世界时间：**隔离夹具同时包含明确、未知和冲突时间事件；验证入口、路由/状态、时间投影与画布，区分控件不存在、遮挡、禁用、状态未更新、读取失败和投影未就绪。
3. **证据：**失败时只保存隔离 fixture 的操作名、耗时、相对 URL、源码修订、视口、项目/任务状态、相关请求结果、页面异常与目标几何；可选 trace 由 `directoryTrace=1` 显式开启、最多 300 条、不自动上传，不含正文、请求体、凭据或附件。
4. **恢复合同：**World Library 与 Story Unit 合并同 URL 在途读，并允许重复挂载在 5 秒内复用刚完成的快照；任何写请求立即失效，时窗结束、失败或超时也释放，不跨 Owner 失效缓存结果。挂起读有明确超时，错项目与 cleanup 晚到结果可解释丢弃，合法空项目不再统一退避 7.56 秒。
5. **首屏身份：**Story Unit 自身的 `linkedEntityIds`、items 和 collection points 是正式成员读来源；不再等待较慢的 Canon enrichment 才显示直接节点与集点，也不因此接纳未确认 draft。
