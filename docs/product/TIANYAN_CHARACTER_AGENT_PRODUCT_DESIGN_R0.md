## 一、什么叫做"这个角色有生命感"

产品核心给的是机制语言（`:417` 稳定身份、状态、记忆、关系、知识边界、可被调用的响应方式；`:43` 让角色依据自己的知识和记忆行动）。作者不会用机制判断一个角色活没活。**本文采用下面十条现象判据**——每条都是作者能在屏幕上验证的一件事，本文之后所有界面要求都必须挂到某一条上。

| # | 作者心里的问法 | 作者要看到什么 | 挂到 |
| --- | --- | --- | --- |
| P1 | 他这一刻是什么样 | 一句他现在能说出口的话，而不是一个数 | 状态 |
| P2 | 他记得什么，记错了什么 | "他记得的版本"和"实际发生的"两栏并排 | 记忆 |
| P3 | 他不知道什么 | "不知道"是一格**有内容的位置**，不是空白 | 知识边界 |
| P4 | 他跟每个人都不一样 | 同一个他对 A、对 B 的两副样子同时可见 | 关系 |
| P5 | 他会不会说不 | 一次他被拦住的记录，写着被哪一条拦住 | 人格 |
| P6 | 他变过没有 | 前面和后面，中间挂着那件事 | 成长 |
| P7 | 他为什么走到这一步 | 偏移点可以点开，看到拽开他的因 | 命运轨迹 |
| P8 | 他是他自己还是我写的所有人 | 他的说话方式与其他角色在同一屏可比 | 档案／人格 |
| P9 | 我不看他的时候他在干什么 | 他此刻在做的、不需要我看着他也在推进的事 | 后台 |
| P10 | 这是真的他还是候选的他 | 任何时候一眼能分清权威状态 | 横切 |

**四条承重墙**（其余六条都建立在这四条之上）：

1. **他有一个此刻。** 没有"截至哪一刻"的界面，状态、记忆、关系全部失去意义——它们都是随时间变化的东西。
2. **他有一个只属于他的视野。** 这是天衍区别于设定库的唯一硬特征。
3. **他跟每个人不一样。** 关系不是一条条记录，是"他对每一个人的不同"。
4. **他变过，而且变得有据。**

以及一条**反判据**，它比四条更正面的东西都重要：

> 生命感第一次出现的时刻，是作者第一次在屏幕上看到**这个角色不知道什么**。
>
> 一个没有盲点的角色不是活着的人，是一份设定集。

这条决定了本文 §9（知识边界）排在优先级最前面，而不是排在"更高级的命运"之后。

## 二、今天角色界面的形状，以及它为什么不产生命感

角色今天有**四处**界面，不是零，且质量不均：

| 位置 | 覆盖什么 | 实况 |
| --- | --- | --- |
| 中央角色工作面 `product-shell/project-directory/character/CharacterWorkspace.tsx:72-79` | 摘要、角色核心、底线、别名、标签、完整角色资料、关联故事、查询范围、正式关系、可知范围 | 真内容，只读组合既有 Owner |
| 磁吸工作台 9 页签 `components/entity-dock/EntityInspectorDock.tsx:27`（`总览／档案／心理与状态／记忆／关系与知情／人生与事件／演化与命运／Agent 运行／来源与权限`） | 八面全部预留了位置 | 四面真内容、两面诚实占位（`:160`、`:164`）、一面只有计数与深链（`:163`） |
| 女娲上下文检查器 `components/nuwa/NuwaN1Workspace.tsx:744`、`:780-791` | 角色核心／底线／本场目标、已知、信念与误解、听闻、注意力入选与排除、预算 | **全仓唯一"作者看到的 == 模型收到的"** |
| 事件线的两个角色镜头 `event-observation/StoryProgressionWorkspace.tsx:236`（人物知情观察 1–5 人）、`components/EventLineWorkbench.tsx:1057-1068`（角色视角 + 盲区开关） | 亲历／目击／被告知／推断／误解／未知／已否定／存在矛盾 | 已经能"看见他不知道"，见 §9 |

这四处已经覆盖了用户点名八面中的四面真内容。**但把它们全部接满，作者仍然不会觉得角色活了。** 原因不在内容量，在四个结构性问题：

**① 按数据责任区分区，不按作者的问题分区。** 九个页签的切分方式（档案／心理与状态／记忆／关系与知情／人生与事件／演化与命运／Agent 运行／来源与权限）几乎逐条对应后端契约的名字，不对应作者会问的话。P1–P10 里没有一个问法的答案落在"Agent 运行"页签里。

**② 没有一处有时间主语。** 今天没有一个角色界面回答"截至哪一刻"。研究 R0 §2.3 实测：状态投影的作用域是写死的伪值（`branchId:"main"`、`worldTime:{kind:"unknown"}`、`narrativePosition` 取数组下标）。这不是接线问题，是**界面没有为"此刻"留出位置**。

**③ 每面各自单陈，从不并排。** 生命感来自并置：他知道／他以为／事实是；他对 A／他对 B；他从前的样子／现在的样子。今天四处界面里，除视角观察之外没有一处做并置，而并置恰恰是 P2/P3/P4/P6 的唯一实现方式。

**④ 最小单元是"记录"，不是"角色 × 时刻 × 对象"。** 关系列表的一行是"一条 Relation"（`CharacterInspectorCard.tsx:101-113`），记忆列表的一行是"一条记录"（`:80-99`）。作者想问的却是"他**对**张三**现在**怎么样"。单元选错，列表越长越不像人。

**结论**：本文不建议新增页签。建议把八面按作者的问题重组，并且规定每个界面都必须带时间主语和权威条。已有的九页签不是错误——它是**预留得很好的位置**（研究 R0 §6.1 的判断，本文同意），问题是不要把它当成信息架构的最终答案。

## 三、建议的界面结构：一张脸、八个面、一条时间

```
L1  角色的脸      一屏看完他此刻的样子（不提问也能看见）
     │
L2  八个工作面    档案 · 人格 · 声音 · 记忆 · 状态 · 关系 · 知识边界 · 行动史
     │
L3  一条时间      命运轨迹（形状） + 成长（内容） —— 同一批时刻的两种读法
     │
横切  权威条      作者确认 / 候选 / AI 推断 / 派生副本内 / 过期 / 未知（≠空）
```

**L1 是必须新增的一屏，不是可选装饰。** 理由：L2 的八个面都是"问一句答一句"，而生命感来自**不提问时也看得见**。今天最接近 L1 的东西是磁吸工作台的"总览"页签（`EntityInspectorDock.tsx:175`），但它只组装了标题、子类型、角色核心、参与计数与关系计数。

**L3 里命运与成长必须分开。** 产品核心把两者写在相邻段落（`:552-566` 与 `:547`），但它们是两种东西：命运看**形状**（他这一路的高低起伏，可设计、可拖动），成长看**内容**（他在哪一维上不可逆地变了，代价是什么）。合并成一面的代价是两头都不成立——最后必然退化成一个折线图。

八面与十判据的对应：

| 面 | 回答的判据 | 今天 |
| --- | --- | --- |
| 档案 | P8（部分） | 已有，窄 |
| 人格 | P5、P8 | 已有两字符串，缺条目化 |
| 声音 | P8 | 未开始（产品核心 `:539` 明确列了"说话方式"） |
| 记忆 | P2 | 读侧已有，写侧 1/5 |
| 状态 | P1 | 整面占位 |
| 关系 | P4 | 客观关系已有，主观那一半缺 |
| 知识边界 | P3 | **已有，且是全仓最好的一面** |
| 行动史 | P9 的前半 | 只有计数与参与四态 |
| 命运轨迹 | P7 | 整面占位 |
| 成长 | P6 | 未开始 |

## 四、角色档案

**作者的问题**：他是谁，我确定到什么程度。

### 4.1 必须让作者看到

- A-1 一个稳定的他：改名会牵动哪些引用，当场能看到。
- A-2 **每一条档案事实分别带"这条我是从哪知道的"**——作者确认的／AI 提取待确认的／来源原文抽出的。产品核心 `:513` 要求 AI 起草后把已知、推断、未知分开。
- A-3 缺口，不是完整度百分比。产品核心 `:548` 要"丰富度、一致性和缺失项检查"——"缺恐惧、缺出身"是有用的，"档案 72%" 是没用的。
- A-4 档案与正文的分工：哪些字段是"作者钉住的他"（进排演），哪些是"读者看到的他"（正文与卡片分区）。今天这个区分只体现在两个字段的白名单里（研究 R0 §2.1.4）。
- A-5 渐进披露：先给作者当下要理解的，再给常用编辑，最后给完整历史与技术来源（产品核心 `:2121-2129`）。

### 4.2 界面要求

- 档案页是**一张会被事件改写的身份卡**，不是表单。表单暗示"填完就完了"，身份卡允许长出来。
- 逐字段角标 + 点击角标回来源锚点。今天缺的不是数据，`sourceAnchors` 已在契约里（研究 R0 §五 profile 行），缺的是那个角标。
- **分区按内容需要出现，不按标签出现。** 角色卡系统声明了 12 个中文分区名——背景与出身／性格／外观／目标／动机／恐惧／弱点／声音／知识边界／当前状态，加"秘密"与"人物弧线"两种块类型（`src/storyCardPresentation/characterTemplate.ts:265-279`），而引导创建只产出其中三段（`characterPreset.ts:31-35` 的 background／personality／appearance）。**一个声明了但没有内容生产者的分区标签，是对作者的承诺。** 界面要么不显示它，要么显示为"这一格还没有内容，可以从这里补"，不能显示为一个看起来能填的空位。
- 卡片组合系统（`storyCardPresentation` 的 layout／blocks／property-group／connections／media）在应用侧只被消费了 `card.portrait` 与 `card.revisionToken` 两处（`CharacterWorkspace.tsx:74`、`CharacterInspectorCard.tsx:68`、`CharacterDirectoryPanel.tsx:190`、`EntityInspectorDock.tsx:80`）。**"角色卡"作为作者可组合的界面今天不存在。** 曾存在的组合面 `components/CardWorkbench.tsx` 已在 `60ca862` 删除，但 `项目目录导航.md:189` 仍把它写成"修改资料卡片显示"的入口——这条是文档漂移，本文只记录不处理。

## 五、人格

**作者的问题**：他会因为什么拒绝，会怎么选。

### 5.1 本文对人格面的核心主张

**人格界面的验收标准不是"填得全"，是"作者能在界面上指出这一次他是被哪一条拦住的"。**

产品核心 `:530-548` 列了欲望、恐惧、底线、价值观、智力与判断方式、文化水平、素质习惯性格、说话方式。今天进入模型的人格只有两个字符串（`{core, boundaries}`）。补齐字段只是第一步——**如果人格不能否决一个行动，它就不是人格，是自我介绍。**

研究 R0 §4.1-L2 的判断本文完全接受并转成体验要求：今天约束是**措辞不是关卡**。体验后果是作者会在排演结果里看到"一个谨慎求证的人毫无根据地下结论"，并且无法指出这是哪一条被违反了。这种时刻是生命感的净损失。

### 5.2 必须让作者看到

- G-1 人格是**条目**，不是文本块。每条可单独确认、单独引用、单独关闭。
- G-2 每条有强度：**硬底线**（任何时候不许）／**软倾向**（通常这样，但会因压力改变）／**当前阶段**（这一卷之后可以松动）。理由：戏恰恰发生在破底线处；没有强度分层的底线清单会逼作者在"禁止一切"和"只是装饰"之间二选一。
- G-3 **破底线要显示为冲突，不能静默。** 他做了他不该做的事，界面上要说"他越过了第 3 条，因为第 5 条的压力"，并让作者决定这算不算数。
- G-4 每次排演步骤反向标注：这一步用了哪几条人格条目。今天步骤详情显示 intent／speech／action／observableResult（`NuwaN1Workspace.tsx:791`）但没有条目引用。这是 P5 的唯一实现方式。
- G-5 人格的一致性回看：他到目前为止的言行有没有互相打脸——**AI 语义检查，作者触发，结果是候选**（产品核心 `:873`）。

### 5.3 界面要求

## 七、记忆

**作者的问题**：他记得什么，记错了什么，哪一段把他改变了。

### 7.1 必须让作者看到

- M-1 **他记得的版本 vs 实际发生的**两栏并排，偏差要显眼。产品核心 `:1653-1657` 要求记录"是否被欺骗／是否误解／何时知道／是否改变了后续选择"。这是记忆面最有戏剧性的一格：作者看到的不是"少了一条记录"，是"他抱着一个假的记忆活了几十章"。

- M-5 分层。**产品核心 `:1623` 明确"角色记忆不是简单的三个大文本框"。** 因此本文主张：长期／短期／最近（`:540-542`）在界面上**不是三个输入框，而是一个"他此刻想得起来的东西按什么顺序出现"的召回视图**。把它们做成三个框，等于把系统的行为手工交给作者维护，直接违反 `:550`。

### 7.2 界面要求

- 每条记忆一行必须能回答四问：他经历了什么／他从谁那里知道的／他当时信了几分／这件事后来改变了他哪一步。今天一行能回答第一问和它的来源。
- 记忆面与视角观察（§9）共用选择：**"他此刻能想起来的"和"他现在知道的"是同一批证据的两种读法**，不要在两处各造一份列表。
- 排演内的记忆增量今天有契约但没有应用者（研究 R0 §2.2.3 的 `NuwaMemoryDelta`）→ 界面上**不要先给"候选记忆"留位置**。这是最容易造出误导性空壳的地方。

## 八、状态

**作者的问题**：他现在是什么样。

这是八面里唯一**整面都是占位**的一项（`EntityInspectorDock.tsx:160` 逐字写着"状态投影合同已定义，但当前没有生产喂入；本面板不做无来源推断"）。这个诚实占位本文建议**保留到真有生产者为止**（研究 R0 §6.1 同判）。

### 8.1 本文对状态面的核心主张

**状态不是数值，是"他现在可以说出口的句子"。**

产品核心 `:543` 给了一个完美的词表：**知道 · 相信 · 怀疑 · 误解 · 不知道**。契约也已逐字对齐它（六种认知权威，研究 R0 §2.3.1）。状态面要做的不是把 8 个维度画成 8 个仪表，而是把每一维呈现为**一句带来源和权威角标的陈述**。

具体主张：

- S-1 一维一行，每行一句人话 + 角标（世界事实／作者规划／候选／未知）+ 来源事件。
- S-2 **"我不知道"是一格内容，不是空白。** 这一条决定状态面是活的还是死的。
- S-3 必须显式带"截至哪一刻"——P1 的落点。没有时点的状态没有意义，因为有状态的界面就等于宣布有一个时间主语。
- S-4 冲突态并列显示两条，不合并（契约已有 `conflicts`／`staleSources`，研究 §2.3.1）。作者宁可看到"我这里存了两条互相矛盾的"，也不要系统替他挑一条。
- S-5 **六词词表要成为全产品的通用状态视觉**，不能状态面用一套、视角观察用另一套（今天 `StoryProgressionWorkspace.tsx:281` 用的是"相信·未证实／推断/怀疑／误解·被错误信息误导"，措辞已不完全一致）。

### 8.2 维度优先级（体验排序，不是实现排序）

契约声明 8 维（`characterStateProjection.ts:24`：`physical｜location｜possession｜knowledge｜belief｜goal｜commitment｜perceived_relation`）。今天只有 `knowledge`／`belief` 有产出。本文主张**先做作者最容易验证的三维**：

1. **location（他在哪）** — 作者一眼能判断对错，且是"移动不合理"检测（`:947`）的落点。
2. **possession（他手上有什么）** — 与物品 Agent 的持有人链共用证据（`:597` 明确持有人是一条可追踪关系而不是文本字段）。
3. **physical（他身体怎么样）** — 伤、病、疲，是读者最敏感的东西。
4. `goal`／`commitment` 是"他会做什么"的直接输入，价值最高，但它要求 §14 的决策改造，属后段。
5. `perceived_relation` 归关系面（§10）。

理由：前三维是**可证伪**的。心理维作者无法验证"你凭什么说他焦虑"，可证伪性一旦失去，这个面板就从工具变成噪音。

### 8.3 三档

| 档 | 内容 |
| --- | --- |
| **已有能力** | 位置已预留且占位诚实（`EntityInspectorDock.tsx:160`，含"非心理测评"的小字）；契约侧 8 维／6 权威／冲突／过期／规划／候选全套已在并带测试；`explainStateTransition` 的中文输出（"由事件 X 形成／缺少事件依据"）已经是可以直接上屏的文案（研究 R0 §五） |
| **缺失能力** | 一切真实内容：状态算出来即被丢弃，只有 hash 活成"上下文版本"一个字符串（`:182`）；6/8 维零生产者；作用域是写死伪值；**唯一持久状态 Owner 在校验层拒绝角色主体**（`storyStudioWorkspaceOperations.ts:1540-1541`，研究 R0 §2.3.2 —— 这是产品裁定，不是界面缺陷）；"截至哪一刻"；"我不知道"作为一格；六词词表的统一视觉 |
| **未来幻想** | 情绪值／压力值／理智值（SAN）滑块面板；状态随时间自动漂移（无调度器，见 §12-DQ10）；心理测评式雷达图；把 `confidence: number`（`temporalProjection.ts:29,42`、`derivedEventLineR1.ts:54-70`）拿来当状态高度——研究 R0 §2.6.5 警告过的最省事实现，本文把它列为禁止项而非选项 |

## 九、关系

**作者的问题**：他对每个人有什么不同，什么时候开始不一样。

### 9.1 现状是六面里结构最强的一族

`RelationRecordR0` 双时态 + `reviewState` + `evidenceRefs` + `supersedesRelationId`，唯一 Owner，全仓最强（研究 R0 §三"关系"）。作者面已有三处：正式关系列表（`CharacterInspectorCard.tsx:101-113`，显示类型／方向／有效时间／依据数，并能跳"查看支持事件"）、聚焦关系阅读器 `FocusedRelationsWorkspace.tsx`（默认围绕一个人物或地点，带正式方向箭头的 SVG 连线）、双时点比较（`StoryProgressionWorkspace` 的 T1/T2）。并且它守住了产品红线：`:1308` 说关系图谱不是一套事实库，实现就是只读同一 Owner。

### 9.2 本文对关系面的核心主张

**关系面缺的不是结构，是"主观那一半"。**

今天的每一条关系都是**第三人称客观的**：A→B，类型是某关系，依据是某事件。角色生命感要的是**他感觉到的那一条**——他以为张三是他父亲、他不知道李四早已背叛他、他对王五客气是因为怕。

契约里**已经有这一维**：`perceived_relation`（`characterStateProjection.ts:24`）。所以关系面的升级不是新结构，是**把主观关系与客观关系并排显示**。

界面主张：

- R-1 最小单元改成**"这个角色 × 对方"的一行**，一行里两面：*他知道的关系*（来自 Relation Owner，已有）／*他以为的关系*（来自 `perceived_relation`，缺）。这一改动直接把 P4 做实。
- R-2 **不对称必须一眼可见**：我爱他／他恨我。今天两条关系要作者在列表里自己比对。
- R-3 每条关系带"从哪件事开始不一样"，并可回事件线。今天"查看支持事件"已在，缺的是变化前后并排（`supersedesRelationId` 已在 Owner 里）。
- R-4 **关系强度只能是分类 + 理由，不能是数。** 产品核心 `:558` 禁的是"无法解释的神秘分数"，关系面上对应的做法就是"亲密度 62"。可用的写法是"警惕／依赖／敬而远之/亏欠"这类有名有姓的分类，每一类挂着是哪件事造成的。
- R-5 关系面与 §8 状态面的 `perceived_relation` 是同一批数据的两种呈现，**不要在两处各维护一份主观关系**。

## 十、知识边界

**作者的问题**：他不知道什么，以及我什么时候会看到他破功。

### 10.1 这是今天唯一已经能"看见他不知道"的一面，也是全仓最好的一面

必须如实记功，因为这段的完成度高于研究 R0 的摘要给人的印象：

- **知情观察 1–5 人**（`StoryProgressionWorkspace.tsx:236`）：单选看该人物的可知范围，多选进入联合对照，并明写"至少一人可知的事件会保留，并逐人标明未知与误解"。
- **八态词表已上屏**（`EventLineWorkbench.tsx:1068`）：亲历／目击／正式关系告知／有证据推断／已知／误解／未知／**角色未知 · 作者可见盲区**。
- **盲区开关已实现且默认关闭**（`EventLineWorkbench.tsx:1058`）："显示作者可见盲区 / 默认只显示该对象有经历、目击、参与、被告知或推断证据的事件"——这与产品核心 `:861` 的要求逐条对上（默认关闭的独立开关 + 打开后明确标记"角色未知"）。
- **结构生效而非提示生效**：N1 路径上越权事实根本不进 payload（研究 R0 §三"知识边界"），且"作者看到的 == 模型收到的"（`NuwaN1Workspace.tsx:744` + `nuwaN1PiAdapter.mjs:96-116`）。
- **排除身份不外泄**：界面只显示"N 项权限排除（身份隐藏）"（`NuwaN1Workspace.tsx:791` 区段），这既是隐私设计也是反剧透设计。
- 可知范围面板自带反幻觉声明（`CharacterInspectorCard.tsx:121`："未把角色介绍或作者规划当作已知事实"）。

### 10.2 缺的三格，恰好是这一面从"正确"变成"有生命感"的距离

- **B-1 "他以为" 与 "世界事实" 的并排。** 今天"误解"是一个标签（`misunderstood`），不是一格对照。P2/P3 的合取实现方式就是：左栏事实是什么，右栏他信什么，中间那件事让他信错了。产品核心 `:1653-1657` 要求记录"信息是否完整／是否被欺骗／是否误解／何时知道／是否改变了后续选择"——**"何时知道"和"改变了哪一步"两格今天界面里都没有**。
- **B-2 谁告诉他的。** 今天"获知"是**从事件标签和正文正则推出来的**（`eventStoryCrossingKnowledge.ts:214` 按"听闻／得知"标签匹配人名；`:298` 按"已得知／得知／informed"匹配文本）。所以传播链在界面上不可回答——**没有一条"由 A 告诉 B"的记录**，只有"这一条被判定为他获知了"。产品核心 `:1651` 要的"谁从谁那里得知"今天只能靠女娲路径的 `heardStatements`（说话者／接收者／哪一步）——而那是 Run 内的听闻，不是正式故事里的告知。
- **B-3 越界的作者面。** 产品核心 `:942` 把"角色知识越界"列进剧情 AI 检测清单；`validateKnowledgeBoundary`（六种结论含 `boundary_violation`，中文释义"把作者全知或另一角色的秘密错误地共享给了当前角色"）**已写完、带测试、零调用者**（研究 R0 §五）。所以这一面缺的是一个**红色可点的差异格**，不是缺校验。它的失败语义属研究 Q10，本文不裁定，但指出：如果最终选择"标注后仍放行"，界面上必须让作者**主动确认才继续**，否则就是"提醒了但照样越界"，比不提醒更伤信任。

### 10.3 界面要求

- 三栏并排且同时可见：**世界事实 / 作者已确认 / 该角色所知**。这一屏是 P3 的完整答案，也是本文认为最短路径的"生命感发生器"。
- 每一格"他不知道"要能回答**他为什么不知道**：不在场／没被告知／被告知了假消息／作者尚未揭示／他自己推断错了。这五个原因在作者体验上完全不同，不能都写成"未知"。
- 盲区开关打开后的内容必须与角色视图在视觉上强烈区分（今天是虚线边框 + "角色未知·作者可见盲区"标签，`event-line-projection.css:766-778`，方向正确）。**作者面和角色面混淆的代价是作品级的**：作者会把盲区里的东西写进该角色的台词。
- "读者已知／作者已知／角色未知"三方要能在同一张表上被读出来——这是 `:861` 那句话的界面化。

## 十一、命运轨迹

**作者的问题**：我打算他去哪，他实际去了哪，偏的那一段是被哪件事拽开的。

### 11.1 先划清这一面的性质

产品核心 `:554` 已经把它定义死了，本文逐条转述：

- **不是只读统计图**；
- **不是用一个分数评价角色好坏**；
- 它是作者**设计、观察、比较、解释**的工作面；
- 作者可以**直接设计和拖动**目标轨迹（`:556`）；
- 拖动之后 AI 的职责是**定位可能要改的事件／连续片段／集点／单元**，说明受影响区间，提出可审查方案——**不是替他改**；
- 默认只展示综合波动，其他维度折叠（`:558`）；
- 每个轨迹变化能回到关联事件、来源版本、变化原因、角色当时的知识边界和**仍然未知的内容**（`:566`）。

所以这一面的正确形态是**一条可拖的时间轴 + 拖完之后的"要走到这里需要改哪几段"的回话**，不是一张图。今天零图表库、零组件（研究 R0 §2.6.4），因此这一面**不可能被误建成图**，反而是运气。

契约侧质量本文在 §11.3 直接引用：三条轨迹并列（`characterFateProjection.ts:59-61` actual／planned／candidate）、`confidence` 是分类 `"author"｜"rule"｜"model"｜"unknown"`（`:31`）**类型上不可能是数值**、`unknownIntervals`／`conflictRecords` 已在（`:62-63`）、未知不插值、不得把候选冒充已发生、必须复用既有 Event ID。

### 11.2 必须让作者看到

- F-1 两轨起画：**实际**（已确认事件形成）与**规划**（作者直接设计）。第三轨（候选）要等研究 Q4 裁定候选身份语义，第四、五轨（排演、跨分支）**契约里根本还没有**（研究 R0 §2.6.3：产品核心 `:560-566` 要五条，契约只有三条 lane）。

- F-3 未知画成**断口**，不连线（`unknownIntervals` 已给位置）。
- F-4 偏移处可点开 → 显示拽开他的因。既有回溯器（`eventCausalIndex.ts` 的 cause／trigger／necessary-condition／result／downstream-impact）**作者已经在事件线上看到它**，两处必须同一套。

## 十二、角色成长

**作者的问题**：他到哪一步开始不一样了，这一变化站得住吗。

### 12.1 先把三个容易混成一团的东西分开

| | 主语 | 回答 | 界面形态 |
| --- | --- | --- | --- |
| 状态（§8） | 他这一刻 | 他现在是什么样 | 一行句子的集合 |
| 命运轨迹（§11） | 他这一路 | 形状起伏在哪、偏在哪 | 可拖的时间轴 |
| **成长（§12）** | **他前后的差** | **他在哪一维不可逆地变了、代价是什么** | **前后两栏 + 中间那件事** |

产品核心只在完整档案里列了一条"角色成长变化"（`:547`），加上模板的"人物弧线"块（`characterTemplate.ts:267`）。**这是八面里定义最薄的一面**——所以本文先给体验定义，再谈界面。

**成长的定义（本文主张）**：成长 = **同一维度上前后不可逆的差 + 代价**。三个条件缺一个就不是成长：
1. 同一维度（"他从前不信任任何人 → 他现在有两个人可以托付"是同一维；"他变强了"不是同一维，是状态叠加）；
2. 不可逆（还能改回去的叫波动，归 §11）；
3. **有代价**——他因此不能再做某件事、不能再见某个人、失去了某样东西。**没有代价的成长是等级提升，不是人物弧光。** 这一条是本文对这一面最强的产品主张，产品核心未写，需要创始人认。

### 12.2 必须让作者看到

- R1 一句可引用的成长陈述：**"他原来认为 X —— 现在他认为 Y —— 转折发生在事件 Z"**，Z 可点开。
- R2 两个弧线并列：**我打算让他走成的弧线**（作者意图）与**他实际长成的弧线**（投影出来的差）。这与 §11 的规划/实际两轨共享数据、不同读法：命运看形状，成长看内容。
- R3 成长**只能是只读投影 + 作者注意义**，不能是作者手填的字段。理由：产品核心 `:550` 禁止作者在多个页面重复维护相互冲突的字段；成长若可手工填写，就会与状态投影打架。
- R4 每条成长挂"他因此失去了什么"。缺代价格，这一面就退化成成就列表。
- R5 反面同样要有：**他没有成长**（同样的错误犯了三次）应该也是一种可读出来的结果，而不是空白。这往往比"成长"更有戏，也更难——因为它要求"重复"能被识别。

### 12.3 三档

| 档 | 内容 |
| --- | --- |
| **已有能力** | **严格说：无。** 最接近的三处都不是作者面：`compareCharacterStates`／`explainStateTransition` 已写完带测试且零调用者（研究 R0 §9.1-B），其输出中文正是 R1 需要的句式；`character-arc` 作为块类型和女娲任务角色存在（`storyStudioWorkspaceOperations.ts:234`、`nuwaPlanner.ts:22,70-73` 会在有长期压力／关系变化／地位变化时选它），但 `nuwaPlanner.ts:22` 的判据是英文提示词且没有作者面；"人物弧光"四字只作为候选解释文案出现（`storyStudioAuthorControl.ts:2697`） |
| **缺失能力** | 整面：成长维度表；两时刻快照的读取（`projectCharacterState` 已支持 `narrativePosition <=` 过滤，**没有调用者**，研究 §4-L9）；不可逆性判定；代价格；"未成长/重复错误"的识别；作者注意义入口；与 §11 共用时刻轴 |
| **未来幻想** | 成长度百分比／阶段等级（炼气期式的数值台阶）；AI 判定"这个角色的弧光已完成，可以收线"；自动生成"成长建议"直接改写档案 |

## 十八、一句话交付判断

**天衍今天已经有"一个能被读取、真的行动过、而且作者能看到模型看到了什么"的角色，缺的是"一个有此刻、有盲点、对每个人不一样、并且变过"的角色。**

八面里真正缺的界面不是八个新页签——九页签早已把位置留好了——缺的是三件组织性的东西：**一个时间主语（截至哪一刻）、一组并置（他知道／他以为／事实是）、一格正面呈现的"不知道"**。而这三件里的第一件（并置）今天离作者最近：知识边界那一面已经能让他不知道了，只差把它和世界事实摆在同一屏上。
