# 天衍界面设计约束

> 本文记录已实现 Shell 的可验证约束，不是替代产品核心的视觉提案。视觉/体验仍需作者独立验收。

## 布局与焦点

- 八空间是稳定一级导航；工程目录是项目范围的二级导航；中央工作面始终保留路由内状态。
- 目录的打开意图按项目保存。窄屏、详情和天意等临时工作面只能暂停呈现，关闭后恢复路径、选择、滚动和焦点。
- 同一时刻只有一个右侧 ContextDock 工具。空间不足时目录与 Dock 互斥，隐藏栏不得继续占宽或遮挡 composer/末项操作。
- `/tianyi` 的创意/工作与页面天意 Agent 分别表达会话泳道和 Page-scoped Run；不靠同名标签暗示它们是不同事实 Owner。

## 密度与组件

- 使用既有语义 token（字体、间距、边框、圆角、状态色）；避免无业务含义的渐变、阴影和大面积空卡。
- 阅读面优先正文、候选、影响和下一步；技术 ID、版本、运行细节在可展开诊断中保留。
- 一个状态只突出一个主要动作。候选、已确认、冲突、未知、过期与派生状态必须同时使用文字和非颜色线索。
- 列表、目录和画布以稳定 ID 引用对象；选择、筛选和布局不复制 Event、Relation、Canon 或正文。

## 响应式、键盘与错误

- Shell 变更至少人工核对 1440、1195、1152 和 1024：首屏输入、目录/Dock 互斥、无 body 横向溢出、可见末项动作、Esc 和焦点返回。
- 画布保持缩放、平移、适应/定位当前等统一语法；未知时间、冲突和候选必须以诚实状态呈现。
- 加载/错误提示说明数据是否安全以及下一步；内部诊断可展开，不能把运行 ID 或 Provider 细节作为普通作者界面的主文案。
- 自动测试与截图只证明指定状态，不能取代真实模型或作者体验验收。
