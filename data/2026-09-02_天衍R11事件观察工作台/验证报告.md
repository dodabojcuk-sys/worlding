## 产品闭环

- 叙事顺序 × 参与：人物、地点、物品共用 Event 列，参与、见证、明确缺席、未知四态不互相代替。
- 世界时间 × 参与：严格合法日期排序；相对描述、非法日期和未知时间不被伪造成精确先后。
- 角色视角：只允许正式人物；地点和物品保留为参与焦点，不获得知情、信念或误解。
- Event 详情：矩阵表头和单元格都复用同一 Event ID 与既有 Page Context Dock。
- 保存与恢复：URL / localStorage 只含布局、镜头、图层、焦点 ID 与尺度；无正文、关系或 Canon 数据；删除/非正式对象被安全剔除。
- AI 边界：切换、筛选、缩放、保存、刷新都不调用 Provider；关系演变因缺少版本化关系状态而显式禁用。

## 性能与大数据策略

- 纯投影基准：1,000 Events × 5 对象 = 5,000 cells，9 次运行中位数 127.39 ms、最慢 142.50 ms。
- 压力诊断：10,000 Events × 5 对象 = 50,000 cells，单次 1,247.18 ms；该规模不作为同步 DOM 渲染承诺。
- 生产保护：焦点上限 5；可见 Event 列上限 240；超过后给出明确范围提示。矩阵使用稳定 Event 顺序/严格日期排序和独立横向滚动，不引入新的布局依赖。
- 后续门槛：若真实作品经常超过 240 列，应在同一投影合同上增加窗口化或按单元聚合，不能通过丢失 unknown、合并 Event ID 或后台 AI 来提速。
