# R11 事件观察工作台调研报告

调研日期：2026-09-02—2026-09-03
方法：Agent Reach 的 Exa/Jina 一手资料检索、论文/项目页核对、GitHub CLI 只读维护与许可检查、本仓库代码和浏览器基线审计。未复制第三方代码或视觉资产。

## 结论摘要

研究一致指向一个重要分离：**数据语义、观察问题与布局优化不能混成一个轴**。Story Curves 证明叙事揭示顺序与故事时间可并置但不可互换；storyline 系列方法擅长表现实体在时间中的聚散，却常把离散时间片与空间接近当作既定输入；FocalLens 把 POV / focalization 拆成多层心智概念，也恰好说明地点和物品不能被随意投射为“知情者”。因此 R11 采用组合式观察合同，而不把七种线或图做成同级页面。

本轮选择“参与”作为最小闭环，是因为现有正式对象和 Event 标签能诚实回答“谁/何物/何地与事件有明确联系”；关系演变需要历史化关系状态，角色视角需要更严格的心智证据合同，均不应为了界面完整而伪造。

## 逐项研究

### Story Curves

- 解决的问题：非线性叙事中，作品呈现顺序与故事时间顺序不同，读者难以同时把握两者。
- 可借鉴：把叙事顺序与世界时间定义成两个独立坐标；元数据只作为可选叠层；持续时间和跳叙需要明确标记。
- 不适合直接搬用：二维“曲线”不是天衍全部事件语义，也不能承载参与、关系状态和 Canon 权威。
- 风险：故事时间常需人工判断，不能因布局需要补造日期。
- 来源：[Visualizing Nonlinear Narratives with Story Curves](https://storycurve.namwkim.org/file/paper.pdf)，DOI [10.1109/TVCG.2017.2744118](https://doi.org/10.1109/TVCG.2017.2744118)。

### FocalLens

- 解决的问题：从人物与事件层面分析叙事 focalization，并区分内/外聚焦及感知、心理、意识形态等维度。
- 可借鉴：POV 不是“对象参与”的别名；角色视角必须声明观察者与证据维度；对比时保留差异而非压成交集。
- 不适合直接搬用：其研究流程在用户研究前人工校正了 LLM 预测，不能把模型输出直接当正式视角事实；地点和物品不是心智主体。
- 风险：2026 年预印本、样本规模小，适合作为概念启发，不适合作为生产合同的唯一依据。
- 来源：[FocalLens project](https://hridoy100.github.io/project/focallens/)，[arXiv 2604.14456](https://doi.org/10.48550/arXiv.2604.14456)。

### StoryFlow

- 解决的问题：大量实体在连续时间片中的分组、排序、对齐和线条可读性。
- 可借鉴：参与泳道应共享事件列；减少交叉、保持连续身份、按需捆绑是布局目标；布局算法只输出位置。
- 不适合直接搬用：它假定时间片和互动组已作为输入，不能判断天衍中的世界时间、参与事实或关系权威。
- 风险：大规模自动布局会引入位置跳动；R11 先用稳定输入顺序与 CSS 网格，不引入第二布局依赖。
- 来源：[StoryFlow paper](https://www.shixialiu.com/publications/storyflow/paper.pdf)。

### iStoryline

- 解决的问题：作者在自动美化与手工表达之间进行混合式 storyline 编排。
- 可借鉴：高层作者意图应显式输入；自动布局需尊重固定位置与连续性；视图调整与故事事实要分开保存。
- 不适合直接搬用：其编辑操作与数据模型不能成为第二 Event Owner。
- 维护与许可：公开实现 `tangtan/iStoryline.js` 为 Apache-2.0，最近代码推送为 2023-04-01；仅作研究，不纳入依赖。
- 来源：[iStoryline paper, DOI 10.1109/TVCG.2018.2864899](https://doi.org/10.1109/TVCG.2018.2864899)，[iStoryline.js](https://github.com/tangtan/iStoryline.js)。

### PlotThread

- 解决的问题：以强化学习给出 storyline 布局建议，并允许作者与算法共同编排。
- 可借鉴：布局建议必须可拒绝，作者控制与算法输出要分层。
- 不适合直接搬用：RL 训练/服务、建议稳定性和可解释性远超本轮需求；它解决布局质量，不解决 Canon、时间或视角真实性。
- 风险：引入运行时和服务面会增加性能、维护、可重复性与权限成本。
- 来源：[PlotThread paper](http://www.ycwu.org/Files/PlotThread.pdf)，DOI [10.1109/TVCG.2020.3030467](https://doi.org/10.1109/TVCG.2020.3030467)。

### Storyline visualization survey

- 解决的问题：梳理 storyline 的视觉结构、时间模型、优化目标与 53 项相关工作。
- 可借鉴：实体持续身份、交叉最小化、紧凑度、组间连续性是明确的布局指标；多数方法采用离散时间片，空间接近主要表达互动分组。
- 不适合直接搬用：时间片模型会压平区间、未知和并发；空间接近不能被天衍反写为关系或参与事实。
- 风险：2026 年综述虽为开放获取，但较新；它适合指导布局评价，不替代产品领域合同。
- 来源：[The Story(line) So Far](https://www.cg.tuwien.ac.at/research/publications/2026/di_bartolomeo-2026-tss/di_bartolomeo-2026-tss-paper.pdf)，DOI [10.1111/cgf.70499](https://doi.org/10.1111/cgf.70499)，[项目索引](https://velitchko.github.io/storyline-survey/)。

### Elsewise / Bundled Storylines

- 解决的问题：在多个模拟 playthrough 形成的可能性空间中，按可配置叙事维度合并暂时不可区分的状态。
- 可借鉴：未来多元/模拟结果可以在明确维度下做“状态束”，但必须保持来源 playthrough 和分歧点。
- 不适合当前 R11：当前工作台投影一个正式事实内核，而不是许多可比较的全局时间步；LLM 提取维度也不能成为事实。
- 风险：2025-12 预印本，假设与天衍当前合同不匹配；本轮不实现。
- 来源：[Bundled Storylines / Elsewise, arXiv 2601.15295](https://doi.org/10.48550/arXiv.2601.15295)。

### React Flow 与 ELK / elkjs

- 解决的问题：React Flow 提供节点式 UI 与交互，不内置唯一布局；ELK/elkjs 为有向图、端口和层次结构计算位置。
- 可借鉴：布局是独立函数，节点尺寸和边输入应显式；复杂布局可异步计算并保留旧位置。
- 不适合本轮：参与矩阵是共享列的表格/泳道，不需要节点图；更换 ELK 会扩大依赖、位置稳定性和 worker 管理风险。
- 维护与许可核验：`xyflow/xyflow` 为 MIT，2026-09-02 有代码推送；`kieler/elkjs` 的仓库许可正文为 EPL-2.0，2026-08-13 有代码推送。R11 不新增 elkjs，继续复用当前 `@xyflow/react` 与已有布局。
- 来源：[React Flow layouting](https://reactflow.dev/learn/layouting/layouting)，[React Flow ELK example](https://reactflow.dev/examples/layout/elkjs)，[elkjs](https://github.com/kieler/elkjs)，[ELK reference](https://eclipse.dev/elk/reference.html)。

### Ink 与 Twine

- 解决的问题：Ink 是文本优先的互动叙事脚本中间件；Twine 以 passage、链接、变量和 story format 创作非线性故事。
- 可借鉴：分支、状态与输出格式可在未来作为导入/导出语义；编辑器图只是内容导航的一种投影。
- 不适合直接搬用：Ink knot/divert 与 Twine passage/link 都不是天衍的 Event、WorldState、POV 或 Canon Owner；导入时必须映射而不能双写。
- 维护与许可：`inkle/ink` 为 MIT，2026-05-05 有代码推送；`klembot/twinejs` 为 GPL-3.0，2026-08-22 有代码推送。R11 不引入任何代码，许可无传播影响；未来若嵌入 Twine 代码需单独法务/架构评审。
- 来源：[Ink official](https://www.inklestudios.com/ink/)，[inkle/ink](https://github.com/inkle/ink)，[Twine basic concepts](https://twinery.org/reference/en/getting-started/basic-concepts.html)，[Twine passages](https://twinery.org/cookbook/terms/terms_passages.html)，[klembot/twinejs](https://github.com/klembot/twinejs)。

## 采纳 / 延后 / 拒绝

| 方向 | 决定 | 理由 |
|---|---|---|
| 叙事顺序与世界时间分轴 | 采纳 | Story Curves 与现有独立时间线均支持；避免语义冲突 |
| 多对象共享事件列的参与泳道 | 采纳 | StoryFlow/storyline 可读性原则，且现有合同足够 |
| POV 只属于正式角色 | 采纳 | FocalLens 的心智维度与产品权限一致 |
| 视图状态独立保存 | 采纳 | iStoryline 的混合控制启发；本地状态不能进入事实 Owner |
| 关系演变镜头 | 延后 | 缺少版本化关系状态序列 |
| ELK 自动布局 | 延后 | 当前矩阵无需；已有图布局需另做稳定性基准 |
| RL/LLM 自动布局即开即用 | 拒绝本轮 | 成本高，且不能回答事实真实性 |
| Twine/Ink 作为第二故事内核 | 拒绝 | 与唯一 Event/Canon/WorldState 权威冲突 |
| 缺少标签即视为缺席 | 拒绝 | 把未知误写为否定事实 |

## 对 R11 实现的直接影响

- 新增五维观察状态合同与严格兼容矩阵。
- “参与”只投影明确标签，提供参与、见证、明确缺席、未知四态。
- 世界时间仅对严格可解析日期排序；相对文字与未知保持独立组。
- 角色视角过滤为正式人物；地点和物品仍可作为参与焦点。
- 不新增布局依赖，不调用 Provider，不改变 Event/Canon/World/Relation Owner。
