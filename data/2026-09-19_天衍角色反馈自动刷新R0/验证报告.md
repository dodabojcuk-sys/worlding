# TIANYAN_CHARACTER_AGENT_FEEDBACK_REFRESH_R1_ARCHITECTURE_REPAIR 验证报告

## 结论

PR #34 的架构阻断已修复。数据失效权威仍是 `projectProjectionInvalidation`；正式变化完成通知集中在 `localTransport` 成功边界之后；Character Dock 只消费带 project scope 的 typed completion，并将五个必需源作为一个可等待的原子快照提交。

能力边界是：当前浏览器中，经 `localTransport` 成功完成的 project-scoped 正式变化，会通知已挂载 Character Dock 按其自身当前 WorkVersion 重读。本轮没有实现外部 API 实时通知、跨标签页通知、SSE、WebSocket 或轮询。

## 架构与语义检查

- `story-studio-pending-review-changed` 是唯一事件名；Character Dock 仅接受 `kind=projection-change-completed`。
- completion detail 只包含规范化身份字段，是冻结且断开引用的快照；不包含正文、标题、Provider 凭据或对象秘密。
- `projectId` 只来自请求 body；`workVersionId` 只在权威输入/成功回执存在时携带。AuthorControl apply 和 normal confirm 不猜 WorkVersion。
- 成功的每次 apply 最多发一次 completion；请求失败、冲突、stale、abandoned 和 rollback 失败均不发成功通知。
- Golden 和 Tianyi 的 PR 新增 UI 手工 completion emitter 已删除；旧裸 Event 仅保留给 pending-review 兼容消费者。
- planning / timeline planning 是 candidate-only 边界，不会被误报为正式投影完成。

## 快照、并发与失败

- 必需源：character object、world library / identity set、event knowledge projection、formal relations、character memories。
- 五源并行读取，只有全部 resolve 才生成并一次提交 `CharacterDockReadSnapshot`。
- 刷新任一源失败保留上一份完整快照；初次失败不生成完整 Agent 安全预览。
- generation guard 覆盖旧成功、旧失败、scope 变化和 unmount/dispose；运行中 burst 最多追加一轮 tail，每轮均 await 完整快照。
- React development StrictMode 曾暴露组件重挂载时复用已 dispose controller 的真实问题；已改为 effect-scoped controller 并通过最终 E2E。

- 使用真实 UI 在 Tianyi 采纳面完成一次正式 apply，没有手工 dispatch，Dock DOM 移除次数为 0。

- 该 Tianyi 事件与当前角色知识无关，因此前后 revision/digest 保持不变是正确语义；完整重读由五个 loader 的精确计数证明。

### UNMOUNTED_DOCK_REMOUNT_REFRESH

- 用 Golden AuthorControl 的真实 UI apply 单独证明返回角色工作区后的 remount recovery，不冒充 in-place refresh。
- completion event=1；重挂载后 revision 从 `7139c8c1` 变为 `9ca98964`，digest 从 `fnv1a32:07247f6a` 变为 `fnv1a32:8a559a70`。

### 几何与安全

- 1440x900 宽屏证据包含 mounted refresh 前/后；1195x720 紧凑视口无水平溢出，`dockRight=1195=viewportWidth`。
- Provider requests=0，secret sentinel leakage=0，console problems=0。
- 仅有两次隔离 fixture 的正式 apply write：Tianyi confirm 和 AuthorControl apply；没有 UI 额外 story write。
