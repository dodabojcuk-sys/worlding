# 天衍角色 Agent 上下文闸门 R0 验证报告

## 结论

- `CharacterKnowledgeHandoff.contextAccess === "character"` 是构造 `NuwaN1Context` 的前置条件；`display-only` 与 `author` 都在模型上下文构造前 fail closed。
- 角色按稳定 `objectId / observerId + revision` 绑定；显示名不参与身份匹配。
- 作者预览与 Nuwa N1 Pi Provider 工具边界复用 `projectNuwaN1ProviderSafeContext`，并通过同一稳定序列化生成逐字节相同的规范化 JSON。
- 预览始终为 `providerCalls=0`、`writes=0`；没有运行按钮，没有 Event、Canon、数据库、RAG 或新 Agent 框架写入。
- 被排除的作者备注、传闻、角色未知内容只保留计数与稳定原因码；标题、正文和对象名不进入模型安全序列化。

## UI 验收

- 1440×900：林月如上下文显示 2 条已知、0 条信念；沈砚显示 0 条已知、1 条怀疑，怀疑未升级为 knowledge。
- 技术详情只显示闸门合同、digest、同源说明和规范化字节数，不倾倒 JSON。
- 隔离的空 Provider 配置根下，缺失条件明确显示“未配置 Provider”，同时仍显示“Provider 未调用”。
- 1195×720：抽屉覆盖布局可用，文档、Dock 和 Agent 内容横向溢出均为 0。
- 关闭抽屉后，焦点回到 `data-testid="character-open-state-inspector"` 的“查看角色状态”按钮。
- 最终技术摘要为 `fnv1a32:dd11a4d4` / 1901 字节，已在最后一次安全投影收紧后重新截图。
