# 天衍 Runtime Mode 与单入口治理 R0：实施计划

## 目标

用显式运行模式消除开发态的双 UI 入口：开发时只有 Vite（4191）承载 UI，正式构建时只有 Story Studio 服务（4192）承载 UI 与 API。

## 边界

- 不改 Provider Catalog、Embedding、Event、Canon、WorldState、Relation、AuthorControl 或 R11/R11.1。
- 不新增依赖、端口、容器、桌面打包或外部调用。
- 服务继续绑定 `127.0.0.1`；API 路由始终优先，未知 API 始终 JSON 404。

## 实现

1. 在 `apps/story-studio/server/` 定义可审计的 `api-only` / `combined-static` 模式解析；缺省安全地使用 `api-only`。
2. 仅在 `combined-static` 启用 `dist` 与 SPA fallback；`api-only` 对非 API 路由返回最小诊断，不返回应用 HTML、CSS 或 JavaScript。
3. 将 `dev` 和 `serve` 分别绑定到明确模式，并输出唯一正确的入口日志。
4. 扩展既有 E2E 的开发模式断言；新增构建后单端口 smoke、模式单测与架构文档。

## 验收

- 开发：4191 的 HTML 来自 Vite 源码入口，代理可读 4192 API，4192 不能显示 SPA。
- 正式：4192 能返回构建资源和嵌套路由 fallback；未知 API 是 JSON 404；不会启动 Vite。
- 使用 Node 22、Mock/本地伪服务完成测试，不进行真实 Provider 调用。
