# 故事模型与 Agent

> 一句话结论：天衍以统一的故事语义模型管理对象、事件、关系、时间、记忆与知识边界；Agent 是受该模型约束的协作实体而非全知聊天角色。

## 要解决的问题

让长篇故事可持续理解和演化，同时保证人物、物品、地点、事件与世界状态的一致性。

## 核心结论

- 节点、集点和单元构成故事表达的基本粒度；事件线与时间线是同一事件集的不同视图，不能维护成两套事实。
- 角色、物品、地点、组织及自定义对象可成为 Agent，并拥有身份、状态、记忆、关系、目标和知识边界。
- Agent 不等于常驻模型进程；它应按需要取用受允许的上下文并明确区分已知、听说、相信、误解和怀疑。
- AI 新提取的对象先作为候选或未归类内容，经过审查后才进入正式分类与关联关系。

## 可执行方法

1. 设计稳定 ID 的对象、事件、关系、版本和来源引用模型。
2. 以事件驱动对象状态变化，记录人物位置、持有人、身份、关系和知识的变化原因。
3. 在每次 Agent 推演前组装限定上下文，并返回使用范围、推断与不确定项。
4. 导入长篇时保留原文位置，再分段识别章节、节点、集点、单元、关系、伏笔、描写素材和风格候选。

## 风险与边界

- 相邻事件不代表因果；时间未知时只保存范围、相对顺序或未知状态。
- 名称变更、对象合并和关系变更必须影响所有引用，不能产生重复身份。
- 摘要不能替代原始资料，尤其不能抹掉对话、描写、风格或来源定位。
- 角色不得使用其未经历、未获知或仅被误解的信息行动。

## 对我的用途

它确定后端实体、事件存储、上下文组装和长篇导入的基本合同，是所有页面共享数据而不互相漂移的前提。
