# 天衍单角色行动候选 R0 验证报告

## 结论

本轮在 `EntityInspectorDock → Agent 运行` 接通了一个受控的单角色行动候选入口。入口只读取既有角色、Story Unit、角色知情投影与 Provider 配置；服务端重建安全上下文并核对稳定 ID、修订与 context digest 后，最多派发一次 Provider 请求，自动重试为 0。

结果采用 Owner 方案 C：只存在于当前组件内存，明确显示“未保存候选”“未确认 · 未写入故事”，关闭、刷新、换角色、换场景或修改目标即丢失；不进入 Pending Review，不支持恢复或回放。

## Owner 裁定

| 方案 | 裁定 | 理由 |
| --- | --- | --- |
| Story Intake Envelope | 不采用 | 只承载既有实体/关系/事件候选语义，强行映射会把行动候选提前扭曲为 Event。 |
| Nuwa Run / Provider receipt | 不采用为候选 Owner | Nuwa Run 必须保持既有 2–3 人合同；Provider receipt 只保存安全调度元数据与严格投影引用，不拥有候选正文。 |
| 瞬态预览 | 采用 | 不新增数据库、Owner、Provider client 或 tool protocol；生命周期和丢失语义可在 UI 中诚实表达。 |

## 安全与写入边界

- Context gate：`CharacterKnowledgeHandoff.contextAccess=character`。
- 角色绑定：稳定 actor ID + actor revision；不按标题匹配。
- 场景绑定：稳定 Story Unit ID + revision；不使用系统时间冒充世界时间。
- 出站：既有 `characterAgentContextGateway` 安全投影；浏览器不能提交 known facts、beliefs、profile 或 prompt。
- Provider：既有 `aiProviderGateway`，单次请求，`retry=false`，输出上限 512 tokens。
- 结果：复用既有 Nuwa N1 prompt builder、严格 JSON parser、`NuwaN1ActorResult` validator 与 action normalizer；未建立假 Nuwa Run。
- Receipt：配置完成的生产路径复用既有 replay-safe receipt envelope，只记录安全元数据和严格投影状态；不保存 prompt、凭据或原始 Provider response。Fake E2E 不伪造持久回执。
- 写入：Canon、Event、WorldState、Relation、CharacterState、Story Unit、Nuwa Run 全部为 0。
- 泄漏检查：Provider payload、候选、DOM 与 E2E 控制台的秘密哨兵命中均为 0。
