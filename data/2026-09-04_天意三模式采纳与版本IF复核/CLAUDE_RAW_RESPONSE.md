我把六条“已确认边界”当作合同项接受，但对三项待评审问题的解法做反证。下面的编号就是十项答案；末尾集中标注“必须不变量/推荐方案/可推迟项/Founder决定”。

## 1. 总体结论

方向对，但当前模型有一个结构性错误和两个潜在自相矛盾。结构性错误：把“创意/工作/Agent”当成同一层的三个并联模式。**它们不是同一层**——“创意/工作”是交互意图（发散 vs 收敛），“Agent”是执行状态（作者主导 vs 委派执行）。“模式”的正确建模是**意图 × 表面 × 执行者**，而不是三个并列标签。

两个潜在矛盾：
- **(a) 正交性只声明、未交付**。Agent 被限定在“工作+侧边”，那么它就没法跨进“创意”。执行轴被砍掉一半，所谓“两个正交轴”就只是纸面正交。
- **(b) “AI 不是第二 Owner”与“采纳决策读取 AI 摘要”冲突**。只要采纳前的“影响预览”取自 Agent 回执的自然语言摘要，就无法保证决策依据是结构化语义而非 AI 文本。这是全文最硬的矛盾。

可保留的：共享 Work Session、原子化采纳、版本线性、撤销即反向版本。这三块成立。

## 2. 最强反例

场景：Agent 在侧边执行一个受控工具，返回候选（结构化 Event + 关系变更）与回执（一段解释“这制造了 X 与 Y 的悲剧性背叛”）。作者点候选，采纳预览把回执摘要一行渲染成“影响”。此时该候选的关系类型其实是“不明”（工具无法判定），但摘要替它下了断言。作者据摘要点击采纳，**不明确的关系以 AI 文本作依据进入 canon**。

它同时击穿三条：边界1（AI 成第二 Owner）、边界3（采纳应展示“影响”而非摘要）、以及“关系类型不明必须显式暴露”的要求。修复：**采纳上下文必须只用结构化语义 diff 重建，回执摘要从决策链中物理隔离**；结构化 diff 出现“关系类型不明”时，采纳点击直接拒绝，而不是把摘要当依据放行。

## 3. 模式页面矩阵

给定边界下的矩阵，注意两处“空/未激活”单元格揭示了非正交性：

| 表面 \ 意图 | 创意（发散） | 工作（收敛） |
|---|---|---|
| 天意大页 | ✓ 创意模式（仅作者） | ✓ 工作模式（作者；不可 Agent） |
| 侧边天意 | ✗（空） | ✓ 工作+Agent运行（仅页面专属能力） |

两处空/未激活：**侧边+创意**为空，**大页+Agent**未激活。这两格恰恰说明“执行者”轴没有真正正交——它被表面绑死了。推荐建模：模式=意图名（创意/工作），执行=作者/Agent，表面=承载能力；“对话”不再是模式名，而是与二者正交的交互形态（流式/事件流），可与任意模式叠加。

## 4. 状态共享隔离表

数据按“持久权威 vs 交互瞬态”分两栏：

| 数据 | 大页↔侧边 | 归类 | 说明 |
|---|---|---|---|
| Work Session 标识、历史事件序列 | 共享 | 持久 | 同一会话 |
| 来源故事、基础版本 | 共享 | 持久 | 不可变引用 |
| 候选池、回执 | 共享 | 持久 | 回执记实际语义操作与所用药参 |
| 已采纳版本链 | 共享 | 权威 | 唯一 canon |
| 未发送草稿、滚动、悬停、页面选择 | 隔离 | 交互态 | 不落版本 |
| 工具参数（输入态） | **隔离** | 交互态 | 但须被回执**快照**捕获为来源 |

关键点：工具参数“隔离”只能指输入态隔离，绝不意味着不记录。回执必须携带“用了哪组参数、作用在哪个基础版本”，否则回执不可核验、不可回放。

## 5. 采纳状态流

```
选择候选
 → 以结构化语义diff重建影响预览(实体影响/基础版本/范围/受猎Event/Relation/Canon/WorldState/Agent状态)
 → 作者单次原子点击（这就是唯一一次确认）
 → 校验：基础版本未过期 ∧ 无新冲突 ∧ 范围未变 ∧ 关系类型明确
 → 通过：提交新版本 + 生成回执 + 允许撤销
 → 未通过：拒绝该次提交，返回冲突报告（这不是“再次确认”，是拒绝在过期基座上落笔）
```

两条铁则：
- 影响预览**由实际 diff 重建，绝不取自摘要**。
- 采纳后无任何二次确认链；过期/变范围/新冲突是**新决策**，不是旧决策的续问。

## 6. 版本/可能性/IF 模型

按“版本身份 × 规范性 × 生命周期”区分：

| 对象 | 版本身份 | 规范性 | 生命周期 |
|---|---|---|---|
| 候选 | 无 | 假设 | 会话 |
| 工作草稿 | 无 | 非规范 | 瞬态 |
| 可能性 | 无（轻量） | 只读引用 | 会话 / 数轮 |
| 已采纳版本 | 有 | 规范 | 永久 |
| 历史版本 | 有 | 规范（旧） | 永久 |
| 临时分支 | 无/临时 | 假设 | 可 GC |
| 长期 IF | 有（派生副本） | 假设 | 跨会话 |
| 待合并变化（delta） | 无 | 非规范 | 直到并入 |

四组“貌似相近、语义迥异”必须区分：**撤销**＝生成一个反向反转版本，不改历史；**恢复**＝把旧版本状态向前摘取成新当前版本，不是倒带；**旧版本建 IF**＝基于旧基座的 IF 须显式标旧，且永不自动合并；**从 IF 部分并入**＝手工 delta 合并，该 IF 随即分裂为“已并入部分”与“仍挂起部分”，作者的挂起集合变了，须有回执。

## 7. 黄金路径

“三未来”一次生成于工作侧边（Agent 产出三个候选，各自绑定来源故事、基础版本、上下文、依据）→ 作者进入单点决策：
- **采纳**一个 → 原子提交，产生新 canon 版本 + 回执；
- **晋升**一个 → 升级为长期 IF（独立派生副本，跨会话存活）；
- **暂存**一个 → 降为轻量可能性（会话内保留，只读引用旧基座）。

随后作者对已采纳的版本**撤销** → 生成反向版本，历史链完整。注意：只有被“晋升”的那个脱离 GC 威胁，被“暂存”的可能性和另两个未选候选都处于可回收区——这正是第 8 条风险 4、5 的来源。

## 8. 五个最高风险

1. **摘要驱动的采纳**：影响/预览取自 Agent 文本，AI 摘要成为 canon 依据，击穿“非第二 Owner”。
2. **单作者模型在并发下失效**：采纳对基础版本“过期即拒绝”实为单写者设计；故事生产常是团队协作，两个采纳各自从 V5 产生孩子节点，会静默产出分支而非合并，违背“单一 canon + 分支隔离”。
3. **“Agent 仅侧边/工作”与“创意探索也需要委派”**：模式墙把发散与收敛之间的交接切断，作者必须在两个表面间切换，丢失上下文（草稿/滚动/页面选择皆隔离）。
4. **跨来源引用漂移**：边界5说“显式引用只作只读参考”，但 IF 绑定“基础版本+上下文+依据”极易被当作可深拷贝的对象，诱发隐式合并。
5. **可能性 GC 的“重要”判定主观**：谁判定一个可能性“重要”而晋升 IF？阈值不显式，要么静默丢失、要么 IF 无界膨胀；且“从 IF 部分并入”会静默改变 IF 的挂起状态，作者未必追踪。

## 9. 核心冲突修改

两处旧冲突，均出自词汇与流程层面的错误分层：

- **“对话”一词被重载且对标矛盾**（大页“创意/对话”、侧栏“对话/Agent”）。修改：废除“对话”作为模式名，改为三个**正交**维度——意图（创意/工作）、执行（作者/Agent）、交互（对话流/事件流）。任一表面可同时呈现“工作意图+作者主导+对话流”。两处矛盾标签随之消失。
- **“采纳＝生成草稿，再走影响审查与确认链”**。这与边界3直接冲突，是重复确认的反模式。修改：草稿生成移到探索/Agent 阶段；**影响审查并入采纳前的单次点击展示**；采纳＝唯一原子提交，之后只有“撤销”，没有二次确认。

## 10. Founder 决定（最多三个 + 推荐）

1. **单作者还是多人并发？** —— 决定版本线性模型能否成立。推荐：v1 锁死单作者，“基础版本过期即拒绝”，并把“分支合并”显式声明为范围外、可推迟；若未来要团队并行，才引入真合并语义。
2. **采纳是否只认结构化 diff？** —— 决定“非第二 Owner”是否可兑现。推荐：**必须只认结构化语义 diff**；回执摘要仅作展示、置于采纳上下文之外；diff 含“关系类型不明”即拒绝采纳。此条应定为必须不变量。
3. **Agent 是逻辑执行轴，还是仅在侧边的工作专属能力？** —— 决定正交模型是真实还是表象。推荐：逻辑上把 Agent 建为执行轴（可跨意图），UI/安全上保留“仅侧边、仅页面专属能力”作为 v1 表面限制；先接受“创意+Agent”格暂为空的代价，但不要在逻辑层把 Agent 与创意/工作并列成第三模式。

## 标注汇总

**必须不变量**：① AI 永不写 canon，只产候选/回执；② 采纳上下文只用结构化语义 diff，回执摘要物理隔离；③ 采纳＝单次原子点击，无二次确认；④ 基础版本过期/关系不明/新冲突 → 拒绝而非续问；⑤ 回执必须快照所用工具参数与基础版本。

**推荐方案**：意图×执行×表面三轴模型；影响预览前置进单次点击；“重要”=显式作者动作而非自动阈值。

**可推迟项**：分支合并语义（多人并发）；跨故事深拷贝；侧边+创意格激活；可能性→IF 的自动 GC 与归档方案。

**Founder 决定**：上述第 10 项的三条（单/多人、结构化采纳、Agent 轴 vs 表面限制）。
