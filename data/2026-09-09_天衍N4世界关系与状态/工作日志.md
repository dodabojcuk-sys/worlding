## N4-B 合同检查点

## N4-B 持久化检查点

既有 `storyStudioWorkspaceOperations` 的 WorldState 门面现在把 N4 状态历史写入正式地点或物件自身的版本化字段，不增加独立状态库。写入前逐项校验：地点只能使用通行状态，物件只能使用持有状态；支持证据必须是本项目当前修订的已提交 Event；持有者必须是当前未归档对象。读取按观测时间投影，早于变化或没有记录均诚实返回未知；补偿仍是追加记录。

本段验证：世界状态合同和 WorkspaceOperations 集成测试 4/4、Node 22 `typecheck` 与 `lint` 通过。真实 Provider 发送为 0。

## N4-C 女娲合法世界依据检查点

新建 Run 在既有角色事件知情投影之后，才读取已确认关系和 N4 世界状态：关系或状态的支持 Event 必须已经对该角色是 experienced、witnessed 或 informed。注意力只能从这个合法集合里缩减输入，不能向不知情角色泄露状态；两个状态种类保持受限，避免状态批次无界扩张。Run 创建后保存的角色上下文不回读后续状态，旧 Run 保持冻结。

定向回归用同一支持 Event 建立北闸封闭、铜钥匙由林昭持有及林昭—阿芜正式关系：林昭的新 Run 收到两个状态；阿芜既没有状态也没有关系来源；已建立 Run 在服务重启后仍无事后插入的来源。真实 Provider 发送为 0。

## N4-D 自动状态与补偿检查点

本地女娲假服务的“交接钥匙”动作只有在该角色本轮实际 `read_role_context` 中带有铜钥匙状态来源时才可进入自动应用。服务端再次校验对象身份、当前修订、状态历史修订、动作幂等键和正式 Event 依据，随后把变化写进既有对象字段、应用回执与作品版本链。回溯预检要求本批状态仍是当前状态；补偿 Event 确认后追加恢复值，后续作者状态修改会阻断旧批回溯。

定向回归：林昭持有的铜钥匙经高权限自动应用变为阿芜持有；同批 `auto-rollback` 后恢复林昭持有。真实 Provider 发送为 0。

## N4-D 浏览器同稿与恢复交付检查点

隔离的本地故事“雾港 N4-D 浏览器验收”已实际完成：林昭在 `read_role_context` 内看见“铜钥匙持有状态：由 character.林昭 持有”，阿芜没有该世界状态来源；高权限本地 Run 显示 `0 / 12` 模型发送、`0 Provider`，并由林昭步骤产生 `handoff-item`。固定稿 `novel.北闸交接-女娲固定稿` 通过创作界面的“下载 Markdown”在回溯前、后各触发一次。回溯后的冻结产物和它的第一份历史快照均为 SHA-256 `01e9fc977523e6ed46db87d4b6d41ba97fbc6e9aaf07f0215c0f920bcbd18f43`，确认同稿没有被补偿改写。

此过程发现并修复两项真实恢复边界：同一批中重复且同值的同对象交接只写一条可逆状态变化；旧回执若已经保存多次同对象变化，会倒序补偿并只容忍本回溯自己的补偿顶端。前端在失败后重新读取持久回执，恢复按钮保留原幂等操作键。浏览器最终显示“已完成补偿回溯；新的正式版本为 r3”，状态历史最终将铜钥匙恢复给 `character.林昭`；任何非本回溯产生的后续状态仍会保护性拒绝。
